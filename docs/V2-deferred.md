# 미룬 것 (Deferred)

| 번호 | 내용 | 미룬 이유 | 언제 |
|---|---|---|---|
| D-1 | `BaseEntity` 종단 검증 (실제 저장 시 `created_at`/`updated_at` 이 기록되는지) | 엔티티가 아직 없고, 테스트 전용 엔티티를 두면 로컬 DB에 테스트 테이블이 생김 | 11/18 첫 엔티티(users) 작성 때 `@SpringBootTest @Transactional` 로 저장 후, **`JdbcTemplate` 으로 DB 원본 문자열을 읽어** 비교한다(JPA 로 되읽으면 시간대 오류가 가려진다). 시각은 `Clock.fixed` 빈으로 고정하고, 순수 `@MockitoBean Clock` 은 `getZone()`/`instant()` 가 null 이라 NPE 가 난다 |
| D-2 | 매핑표에 없는 스프링 4xx 예외(예: `HttpMediaTypeNotAcceptableException` 406)는 현재 `INTERNAL_SERVER_ERROR` 500 으로 응답됨 | 이 프로젝트에서 실제로 날 가능성이 낮고, 나면 ERROR 로그로 드러남 | 실제로 발생하면 `GlobalExceptionHandler` 에 매핑 추가 |
| D-5 | (코드래빗 PR #3) ① 컨트롤러 **반환값** 검증 실패(`HandlerMethodValidationException.isForReturnValue()` 참)는 서버 오류인데 지금 `INVALID_REQUEST` 400 으로 응답됨 → 500 `INTERNAL_SERVER_ERROR` 로 분리 ② 필수 `@RequestHeader`/`@RequestPart` 누락(`MissingRequestHeaderException`, `MissingServletRequestPartException`)은 400 이어야 하는데 현재 500 (D-2 와 같은 계열) | 이 프로젝트 API 는 헤더·multipart 입력과 반환값 검증을 쓰지 않아 지금은 발생하지 않음 | 11/18 첫 컨트롤러 PR 에서 `GlobalExceptionHandler` 에 매핑 추가하고 테스트로 확인 |
| D-6 | (코드래빗 PR #3) `DatabaseTimeZoneTest` 보강: 옛 설정(`serverTimezone=Asia/Seoul`)이 실제로 9시간 어긋남을 보이는 **대조군** 과, 자정 직전·직후(예: 23:59:59 / 00:00:00) 입력의 날짜 경계 케이스 | 수정 전 실패·수정 후 통과(red→green)로 핵심은 이미 검증했고, 대조군은 별도 연결 설정이 필요함 | 11/20 예외·경계 테스트 정리 때 |
| D-4 | 배포 서버(JVM)의 시간대는 **UTC 또는 Asia/Seoul** 로 둔다. 서머타임이 있는 시간대(예: America/New_York)에서는 서머타임 전환 시각(존재하지 않는 벽시계 시각)이 1시간 밀려 저장될 수 있음 | `serverTimezone` 제거(2026-11-17 결정)의 잔여 한계. UTC·서울은 서머타임이 없어 해당 없음 | 배포 환경을 정할 때(README·실행 옵션에 명시) |
| D-3 | 11/18 엔티티 작성 시 주의 (리뷰에서 나온 것) | 지금은 엔티티·쿼리가 없어 코드로 증명 불가 | ① `@DataJpaTest` 같은 슬라이스 테스트는 `ClockConfig`·`JpaAuditingConfig` 를 자동으로 안 읽으므로 `@Import` 필요(없으면 `created_at` NOT NULL 위반) ② `orders`·`point_histories` 는 BaseEntity 를 상속하지 않으므로 `created_at` 을 직접 매핑할 때 `@CreatedDate` + `AuditingEntityListener` 를 써서 같은 Clock 을 타게 할 것(`LocalDateTime.now()` 직접 호출 금지) ③ 벌크 UPDATE(`@Modifying`)는 `@PreUpdate` 를 안 타서 `updated_at` 이 갱신되지 않음 — 포인트 차감을 조건부 UPDATE 로 구현하면 직접 갱신해야 함. 이때 DB 의 `NOW()`/`CURRENT_TIMESTAMP` 는 서버 시간대를 따라(로컬 compose 는 서울, CI 는 UTC) 앱이 Clock 으로 기록한 `created_at` 과 어긋나므로 쓰지 말고, `LocalDateTime.now(clock)` 값을 파라미터로 넘길 것 |
